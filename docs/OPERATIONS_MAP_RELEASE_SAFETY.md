# 여행갈지도 운영 배포와 DB 변경 절차

## 분리한 이유
과거 `vercel.json`은 모든 Preview/Production 빌드에서 `db:migrate`, `db:seed`, 아고다 가져오기 검사를 자동 실행했습니다. 디자인 배포가 실제 DB를 변경할 수 있으므로 운영 안전성이 낮았습니다.

## 새로운 기본 규칙
- Vercel `buildCommand`: `npm run build` (DB 쓰기 금지)
- DB 구조 변경: 승인된 별도 유지보수 작업에서 `npm run db:migrate` 실행
- 시연용 데이터 보충: 명시적 검토가 필요한 경우에만 `npm run db:seed` 실행
- 아고다 자료 수집: 별도 데이터 작업으로만 실행
- 모든 명령은 해당 환경(스테이징/운영)의 DB 접속 권한을 검토하고 백업 후 실행
- 마이그레이션 실패 시 애플리케이션 배포와 혼동하지 않도록 기록 분리

## 배포 전 확인
1. 운영 Neon schema와 현재 코드가 일치하는지 **읽기 전용** 쿼리로 확인
2. GitHub Actions 지도 회귀 검사 통과 확인
3. Vercel Preview 빌드가 `READY`인지 확인
4. Preview API에서 `category=motel` 등의 5km 필터 결과와 좌표 유효성 확인
5. 모바일 지도에서 category 변경·기본 가락시장역·GPS 권한·외부 지도 길찾기 확인
6. main 병합 후 운영 도메인의 Git SHA가 main과 동일한지 확인

## 복원
새 버전에 장애가 발생하면 **이전 검증된 Vercel 배포로 롤백**하세요. 단, 이미 적용한 데이터베이스 변경은 Vercel 코드 롤백으로 되돌아가지 않으므로 별도 복원 절차를 따릅니다.
